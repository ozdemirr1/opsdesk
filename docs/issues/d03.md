# Finalize remaining API validation and response contracts

Local planning ID: D03. This is not a GitHub issue number.

Suggested priority: P0. Type: design.
Draft origin: grouped Sunday proposal based on reviewed product rules.
Status: awaiting user review; not implemented or published.

## Goal

Close the remaining bounded contract gaps so endpoint work does not invent behavior during implementation.

## Scope

- Organization name/response and membership/Comment input limits; list ordering/projections/filters and count/items consistency.
- Error envelopes and failure precedence, no-op cases, timestamp policy, and remaining transport/server-error behavior.
- Record Attachment migration timing explicitly without adding metadata APIs. Define safe request-log/correlation-ID expectations for Q02.

## Out of scope

- Implementation, new product capabilities, changing approved role/lifecycle rules without separate review.

## Acceptance criteria

- Document exact non-Ticket string bounds, normalization and accepted body/query fields; preserve already-reviewed defaults and scopes.
- Choose Organization/membership/comment ordering and count/items snapshot policy. Decide assignment queue and assignable directory query inclusion/semantics and contradictory-filter errors.
- Finalize nested Organization creation/list and ownership-transfer responses and error details/field paths.
- Specify duplicate/active reactivation, repeated role/assignment/deactivation requests, missing/foreign member targets and overlapping-failure precedence. Preserve reviewed no-op matrix and fixed outcomes.
- Decide malformed JSON/unsupported media-type and unexpected-error mappings without confusing framework defaults with product decisions.
- Select updated_at expression and which business mutations affect it; no-ops preserve it. Define request correlation fields and safe handling of user-supplied correlation values.
- Record Attachment migration inclusion/deferment as a release decision; domain retention does not imply executable table or endpoint.

## Expected tests or review evidence

- Reviewed request/response examples and decision tables for every listed gap; no TBD left for a dependent issue claiming ready to implement.
- Cross-check against D01/D02 to avoid conflicting validators or duplicate email policies. No application tests required to finish design.

## Dependencies

Reviewed Week 09 baseline; no implementation prerequisite.
