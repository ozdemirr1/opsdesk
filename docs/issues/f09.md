# Implement membership role changes and deactivation

Local planning ID: F09. This is not a GitHub issue number.

Suggested priority: P1. Type: feature.
Draft origin: grouped Sunday proposal based on reviewed product rules.
Status: awaiting user review; not implemented or published.

## Goal

Allow reviewed peer management and self-leave without revoking eligibility while active work remains.

## Scope

- PUT /organizations/{organization_id}/memberships/{membership_id}/role; DELETE the same membership resource; DELETE /organizations/{organization_id}/memberships/me.
- Shared active-actor/Organization guards, current membership checks, handover evaluation, retained rows and MembershipResponse.

## Out of scope

- Ownership transfer, global User deactivation, Organization suspension, automatic reassignment.

## Acceptance criteria

- Admin/owner may edit or deactivate another active non-owner member, including admin peers. Customer/agent cannot manage others.
- Ordinary self-role change and owner edits are denied; supplied owner role is rejected. Non-owner self-leave is separate and subject to handover.
- Changing to customer or deactivating requires no open/in_progress assignments in the target Organization. Admin-to-agent preserves eligibility and succeeds despite active work.
- Work in a different Organization does not block this membership change. Resolved/closed assignment references remain intact.
- DELETE changes is_active, never hard-deletes. Successful mutations return 200 after commit; denied/failed changes preserve records.
- Repeated requests and missing/foreign target errors follow D03; concurrent claims/role changes use D04. Static /me and numeric member paths are distinguished.

## Expected tests or review evidence

- Peer admin management, non-owner leave, owner/self-role bypass rejection, and tenant boundary failures.
- Admin-to-agent with active work succeeds; demotion-to-customer/deactivation with open/in_progress work fails unchanged.
- Other-tenant work does not block scoped changes; inactive row and historical relationships survive.
- Concurrent assignment and eligibility revocation preserve invariants; injected failure rolls back.
