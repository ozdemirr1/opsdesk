# Create the ticket schema

Local planning ID: B04. This is not a GitHub issue number.

Suggested priority: P0. Type: schema.
Published issue: [#8](https://github.com/ozdemirr1/opsdesk/issues/8).

Snapshot of the initial published scope, 13 September 2026. Follow GitHub for
current status and scope discussion; this file is not a live progress tracker.

## Goal

Apply the Ticket table with strict participant tenant consistency and bounded state vocabulary.

## Scope

- Implement all reviewed Ticket columns, bigint identity PK, text constraints and timestamp defaults.
- Required Organization/requester/creator; optional assignee with MATCH SIMPLE; direct Organization FK plus three composite membership FKs, all ON DELETE RESTRICT.
- Implement status/priority CHECKs and UNIQUE(organization_id, ticket_id) for future children.

## Out of scope

- Endpoints, transition/assignment authorization, Comment/Attachment tables.

## Acceptance criteria

- Upgrade to the Ticket revision, downgrade to its predecessor, and re-upgrade preserve pre-existing identity/Organization tables and their test records.
- Restore schema before ordinary tests; constraints reject cross-tenant/nonexistent participants and invalid status/priority.
- NULL assignee is valid; NULL requester/creator/Organization is invalid. Match agreed database-level text rules and timestamp defaults.
- FKs establish existence/tenant consistency, not active membership, eligible roles, or transition authority. Defaults do not auto-refresh updated_at.

## Expected tests or review evidence

- Exercise cross-tenant rejection separately for requester, creator, assignee, plus valid same-tenant and NULL-assignee insertions.
- Referenced memberships cannot be deleted; verify direct Organization FK, vocabulary/text constraints, required fields and defaults.
- Migration predecessor preservation and updated cleanup allowlist.

## Implementation evidence — 30 September 2026

- `TicketRow` and Alembic revision `31be9023cfb2` implement the reviewed columns,
  named constraints, defaults, tenant-consistent composite foreign keys, nullable
  assignee behavior, and restrictive parent deletion.
- Catalog-level integration tests inspect columns, defaults, PK/unique/CHECK names,
  foreign-key targets, `MATCH SIMPLE`, and `ON DELETE RESTRICT` directly in PostgreSQL.
- Constraint tests cover accepted boundaries and vocabulary, explicit NULL rejection,
  cross-tenant and nonexistent participants, repeated titles, application-rule
  boundaries, unchanged `updated_at`, and referenced-membership deletion.
- The isolated migration-cycle test downgrades only the Ticket revision, proves that
  pre-existing identity records survive, re-upgrades to head, and restores the guarded
  database even when the test body fails.
- Cleanup allowlists and revision guards include Tickets and delete child rows before
  their referenced memberships. Final full-suite and hosted-CI evidence is recorded in
  the pull request that closes GitHub issue #8.
