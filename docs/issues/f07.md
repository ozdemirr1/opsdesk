# Implement staff-only membership directory

Local planning ID: F07. This is not a GitHub issue number.

Suggested priority: P1. Type: feature.
Draft origin: Sunday conversation draft and mentoring review. Status: awaiting consolidated backlog review; not implemented.

## Goal

Let staff list Organization memberships with a minimal projection and scoped pagination.

## Scope

- GET /organizations/{organization_id}/memberships; role/is_active filters; reviewed ordering/pagination.

## Out of scope

- Membership mutations, assignment, global User search, profile fields; assignable filter until D03 explicitly includes/finalizes it.

## Acceptance criteria

- Active User, active target membership, active Organization; only agent/admin/owner. Customer receives 403 permission_denied when other guards pass.
- No active membership returns 403 organization_access_denied; suspended target returns documented suspension error.
- Items contain only membership_id/organization_id/role/is_active; no global email or User profile.
- Filters/counts stay in target Organization; empty filtered set returns the standard 200 envelope; invalid query follows contract.
- Membership active state is not an assignment-eligibility guarantee. Read changes no state.

## Expected tests or review evidence

- Each staff role succeeds; customer, foreign/inactive membership and suspended Organization fail.
- Scoped role/is_active filtering and counts, empty results, exact fields, inactive target rows when matching filter.
