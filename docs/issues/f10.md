# Implement atomic organization ownership transfer

Local planning ID: F10. This is not a GitHub issue number.

Suggested priority: P1. Type: feature.
Draft origin: grouped Sunday proposal based on reviewed product rules.
Status: awaiting user review; not implemented or published.

## Goal

Transfer ownership between eligible members while preserving exactly one active owner for an active Organization.

## Scope

- POST /organizations/{organization_id}/ownership-transfer with target_membership_id; one coordinated transaction.

## Out of scope

- Multiple owners, billing, invitations, global account or Organization suspension.

## Acceptance criteria

- Only the active current owner in the active Organization may transfer to a different active User with active same-tenant admin membership.
- Old owner becomes admin and target becomes owner; both persist together and are returned in the finalized 200 projection after commit.
- No ordinary role-update bypass. Preserve IDs and assignment references; owner-to-admin preserves assignment eligibility.
- Use the reviewed mutation ordering and locks compatible with the immediate partial unique index. Atomicity does not mean simultaneous SQL statements.
- Failure leaves both roles unchanged. A stale former owner cannot repeat the operation as owner.

## Expected tests or review evidence

- Successful handoff, wrong roles/tenant/self/inactive recipient rejection, and rollback between role updates.
- Concurrent transfers and recipient role/deactivation changes follow D04 without zero/multiple active owners in committed valid state.
- Existing active assignments survive; safe response includes no private User data.
