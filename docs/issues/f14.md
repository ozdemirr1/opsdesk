## Goal

Add an append-only conversation to visible Tickets with tenant-consistent authorship.

## Scope

- Comment persistence model and Alembic migration from the reviewed relational design.
- POST and GET /organizations/{organization_id}/tickets/{ticket_id}/comments; content validation, actor-derived author and scoped listing.

## Out of scope

- Comment edits/deletes, internal notes, Attachments or file storage.

## Acceptance criteria

- Comment has fixed Ticket/Organization/author membership; both composite FKs enforce the same tenant and RESTRICT referenced parent deletion.
- Active actor/membership/Organization and Ticket visibility required. Posting additionally obeys role rules and allows only open/in_progress/resolved.
- All roles are denied posting to closed; reading closed follows Ticket visibility. Comments do not change status.
- Only content accepted for posting; derive parent and author. Valid post returns 201 CommentResponse after commit. No edit/delete endpoints or internal notes.
- List applies finalized ordering/pagination and returns only this Ticket's comments. Existing authorship survives membership deactivation without granting access.
- Posting versus closing coordinates per D04; failure/denial creates no Comment and leaves relevant Ticket state unchanged.

## Expected tests or review evidence

- Schema predecessor migration cycle, composite author/Ticket boundary tests, restricted parent deletion, text validation and cleanup allowlist.
- Customer-own and staff visibility, forbidden author/parent fields, posting in each state and read/write distinction.
- Posting-to-closed and cross-tenant rejection; rollback; concurrent closing/posting; safe projection/pagination.
