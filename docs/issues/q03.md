# Run guarded PostgreSQL integration tests in CI

Local planning ID: Q03. This is not a GitHub issue number.

Suggested priority: P1. Type: quality.
Draft origin: grouped Sunday proposal based on reviewed product rules.
Status: awaiting user review; not implemented or published.

## Goal

Execute real migration and data tests on a disposable isolated CI PostgreSQL target.

## Scope

- Extend CI with separate database-test job and test-only credentials/service provisioning.
- Run migration verification then restore schema and execute guarded data tests in the documented order.

## Out of scope

- Application container builds, Compose stack, production database access, deployment.

## Acceptance criteria

- CI target passes the same exact database/server guard contract; no development/production credentials are available.
- Use a job-local disposable PostgreSQL service; no repository Dockerfile or Docker Compose configuration is introduced.
- One suite owns its database at a time. Explicit concurrency cases coordinate within tests and finish before cleanup.
- Failures in migration, cleanup or tests fail the job and preserve safe diagnostics; fast suite remains distinct.
- CI executes all available integration tests as later features add them; no unsupported claim that missing feature tests passed.

## Expected tests or review evidence

- Successful migration/data run; rejected-target guard tests; cleanup and migration restoration failure propagation; safe logs.
