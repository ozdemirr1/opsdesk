Status: awaiting user review; not implemented or published.

## Goal

Change operational priority and responsibility under the separate role, resource, state and eligibility rules.

## Scope

- PUT /organizations/{organization_id}/tickets/{ticket_id}/priority; PUT and DELETE /organizations/{organization_id}/tickets/{ticket_id}/assignment.

## Out of scope

- Status transitions and reopening cleanup, assignment at creation, automatic background handover.

## Acceptance criteria

- All shared guards and visibility checks apply. Staff can change priority in open/in_progress; customer cannot.
- Agent/admin/owner may assign unassigned open work to eligible self/another member. Agent reassigns/removes only their own existing assignments; admin/owner may manage any in-scope assignment.
- Target must be active User and active same-tenant agent/admin/owner membership. PUT requires non-null assignee; use DELETE for removal.
- Reassignment allowed open/in_progress; ordinary removal only open. Resolved/closed reject ordinary assignment/priority mutation.
- Authorized unchanged priority and admin removal of empty open assignment return 200 without timestamp writes. Other repeats follow D03.
- Actual changes return committed TicketResponse and refresh updated_at per finalized policy. Concurrent claims cannot silently overwrite another successful claim.

## Expected tests or review evidence

- All role/resource/state combinations, customer denial, foreign/inactive/ineligible target denial.
- Eligible reassignment in_progress succeeds; direct unassignment fails. Agent repeating transfer after losing assignment gets denied.
- Selected no-ops preserve timestamps; true mutations change expected fields only; rollback and competing claims preserve rules.
