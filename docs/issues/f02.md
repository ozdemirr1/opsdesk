# Implement user registration

Local planning ID: F02. This is not a GitHub issue number.

Suggested priority: P0. Type: feature.
Draft origin: Sunday conversation draft and mentoring review. Status: awaiting consolidated backlog review; not implemented.

## Goal

Create a global User with safe password storage and canonical-email uniqueness.

## Scope

- POST /users with only email/password; reviewed validation and normalization; maintained hashing library and reviewed hashing policy.
- Commit User before returning 201 UserProfile; server controls User ID and active state.

## Out of scope

- Login, token issuance, memberships, email verification/delivery.

## Acceptance criteria

- Store canonical email and password hash, never plaintext. Responses/errors exclude plaintext/hash/secrets.
- Reject extra/missing/invalid fields with 422 validation_error. Create no Organization or Membership.
- Duplicate email maps only the known uniqueness violation to the contract response; unrelated persistence failures are not duplicate-email conflicts.
- Failed insertion/commit returns no success and leaves no new User.

## Expected tests or review evidence

- Valid registration, hash verification using the original password and library, safe response projection.
- Missing/invalid inputs; injected user_id/is_active/role are rejected.
- Coordinate two overlapping attempts with independent sessions: one 201, one documented conflict, one persisted User. Join both before cleanup. Verify constraint/error mapping independently.
- Insertion and commit failure rollback; separate persisted-state verification.
