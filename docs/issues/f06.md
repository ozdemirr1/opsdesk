# Implement organization listing and detail visibility

Local planning ID: F06. This is not a GitHub issue number.

Suggested priority: P1. Type: feature.
Published issue: [#15](https://github.com/ozdemirr1/opsdesk/issues/15).

Snapshot of the initial published scope, 13 September 2026. Follow GitHub for
current status and scope discussion; this file is not a live progress tracker.

## Goal

Expose basic Organizations only through the caller's active memberships.

## Scope

- GET /organizations and GET /organizations/{organization_id}; is_active filter, pagination and reviewed projections.

## Out of scope

- Organization mutations, member directory, Ticket access, global admin browsing.

## Acceptance criteria

- Active User and own active membership required; both active and suspended Organizations are visible. Inactive membership removes access.
- Missing/inaccessible Organization detail uses 403 organization_access_denied.
- List uses items/total_count/limit/offset, finalized ordering and count consistency; filters only narrow authorized scope.
- Detail returns organization_id/name/is_active; list may include only the actor's minimal membership projection. No other member profiles.
- Empty matching collection is 200. Reads mutate nothing and grant no child-resource access for suspended Organizations.

## Expected tests or review evidence

- Active/suspended visibility; inactive and foreign memberships; matching missing/inaccessible errors.
- Scoped filtering/counts, empty lists, pagination bounds, exact response projection and no writes.

## Implementation checkpoint — 5 October 2026

- Implemented protected `GET /organizations` and
  `GET /organizations/{organization_id}` using the authenticated active User and the
  caller's current active OrganizationMembership as the complete visibility boundary.
- List responses include active and suspended Organizations, exclude inactive and
  foreign memberships, order by `organization_id ASC`, and expose only the reviewed
  Organization plus own-membership projections.
- `is_active` accepts only exact lowercase `true` or `false`. Pagination uses the
  reviewed defaults and bounds. Unknown or repeated query keys return the safe
  `422 validation_error` envelope without reflecting unknown names or values.
- Count and page derive from one PostgreSQL statement over one visible-set CTE.
  A total-row outer join preserves `total_count` for empty pages and offsets beyond
  the result set. The query takes no row locks.
- Missing, foreign, and inactive-membership detail targets all return the same
  `403 organization_access_denied`; suspended Organizations remain readable but this
  grants no child-resource access.
- Fast input, service, HTTP, transport, and regression tests passed. Guarded
  PostgreSQL tests proved tenant scope, active/suspended visibility, filtering,
  stable pagination, empty and beyond-offset pages, matching detail denial, no writes,
  and one unlocked count/page statement.
- Final local snapshots passed separately: `337` non-integration tests with `150`
  cases deselected, `147` integration tests, and `3` schema tests. Alembic remained
  at `31be9023cfb2 (head)` with no pending operations or metadata drift.
- Hosted CI, pull-request review, merge, and issue closure remain pending. These
  results do not claim Ticket creation or other child-resource access.
