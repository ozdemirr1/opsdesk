# Implement organization listing and detail visibility

Local planning ID: F06. This is not a GitHub issue number.

Suggested priority: P1. Type: feature.
Published issue: [#15](https://github.com/ozdemirr1/opsdesk/issues/15).

Snapshot of the initial published scope, 13 September 2026. Follow GitHub for
current status and scope discussion; this file is not a live progress tracker.

## Goal

Expose basic Organizations only through the caller's active memberships.

## Scope

- GET /organizations and GET /organizations/{organization_id}; is_active filter, pagination and reviewed projections.

## Out of scope

- Organization mutations, member directory, Ticket access, global admin browsing.

## Acceptance criteria

- Active User and own active membership required; both active and suspended Organizations are visible. Inactive membership removes access.
- Missing/inaccessible Organization detail uses 403 organization_access_denied.
- List uses items/total_count/limit/offset, finalized ordering and count consistency; filters only narrow authorized scope.
- Detail returns organization_id/name/is_active; list may include only the actor's minimal membership projection. No other member profiles.
- Empty matching collection is 200. Reads mutate nothing and grant no child-resource access for suspended Organizations.

## Expected tests or review evidence

- Active/suspended visibility; inactive and foreign memberships; matching missing/inaccessible errors.
- Scoped filtering/counts, empty lists, pagination bounds, exact response projection and no writes.
