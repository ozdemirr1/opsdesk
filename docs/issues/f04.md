# Implement authenticated current-user resolution

Local planning ID: F04. This is not a GitHub issue number.

Suggested priority: P0. Type: feature.
Published issue: [#13](https://github.com/ozdemirr1/opsdesk/issues/13).

Snapshot of the initial published scope, 13 September 2026. Follow GitHub for
current status and scope discussion; this file is not a live progress tracker.

## Goal

Validate protected bearer requests and supply the currently active persisted global User.

## Scope

- Reusable authentication dependency and GET /users/me.
- JWT verification through the maintained library before trusting sub; load current User every protected request.

## Out of scope

- Login/registration, token issuance, Organization/Ticket authorization, refresh/MFA/reset.

## Acceptance criteria

- Malformed/expired/invalid tokens or missing/inactive current User produce 401 unauthenticated with WWW-Authenticate: Bearer.
- Validate signature, permitted algorithms and required claims/types per D02. Return 200 UserProfile with only user_id/email/is_active.
- Do not rely on token-cached active state or infer Organization access. Authentication writes no business records.
- Database failure is an infrastructure failure, not a fabricated 401; errors/logs exclude tokens/secrets/internal details.

## Expected tests or review evidence

- Valid identity, all token validation failures, nonexistent User, and deactivation after issuing the same otherwise-valid token.
- Correct bearer challenge, minimal response, no writes, DB failure not mapped to 401, safe outputs.
- Controlled signed fixtures/time/settings independent of a live login endpoint or developer .env.

## Implementation evidence — 28 September 2026

The feature branch implements maintained-library HS256 validation with a fixed
algorithm, signature verification, exact required claims, strict claim types and
relationships, issuer/audience checks, zero-leeway expiration, and an injected aware
UTC clock. Only the validated positive bigint subject reaches current-user resolution.
The reusable dependency then loads the User from PostgreSQL for every request and
requires the persisted identity to remain active before `GET /users/me` returns the
minimal public profile.

Unit and HTTP tests cover the complete token rejection matrix, missing and incorrect
authentication schemes, validation before database access, safe bearer challenges,
minimal response projection, current-user service behavior, configuration failures,
and propagation of database failures instead of disguising them as authentication
failures. The focused suite passed 101 tests without warnings.

Seven PostgreSQL tests cover a controlled signed token independent of login, missing
and inactive persisted Users, malformed/wrongly signed/expired tokens, no authentication
writes, and a real `register -> login -> /users/me` flow. Reusing an otherwise-valid
token after deactivating its User produced 401, showing that active state is reloaded
instead of cached in token claims. Full regression, hosted CI, PR review, merge, and
issue closure remain pending.
