# Implement ticket lifecycle transitions and reopening cleanup

Local planning ID: F13. This is not a GitHub issue number.

Suggested priority: P1. Type: feature.
Draft origin: grouped Sunday proposal based on reviewed product rules.
Status: awaiting user review; not implemented or published.

## Goal

Apply the reviewed transition and same-status matrices with atomic conditional assignment cleanup.

## Scope

- PUT /organizations/{organization_id}/tickets/{ticket_id}/status; current-state authorization and coordinated update.

## Out of scope

- New transitions, background cleanup, full assignment history, general customer assignment authority.

## Acceptance criteria

- Implement every allowed transition and actor scope in ticket-lifecycle.md; unlisted real transitions are denied and closed is terminal.
- Entering in_progress or resolved through listed forward transitions requires an eligible assignee. Customer may close/reopen only their own resolved Ticket; agents act on assigned-to-self, admins/owners within tenant.
- On authorized return to open, preserve eligible assignee, clear ineligible assignee, or preserve NULL in the same transaction as status. Customer cannot choose a replacement or clear an eligible assignee this way.
- Same-status 200 requires the explicit same-status permission table; visibility alone is insufficient. No timestamp refresh or cleanup on no-op.
- Authorize using current state before cleanup; failure leaves status/assignment/updated_at unchanged. Reopening replaces the current assignment value, not a full historical audit trail.
- Separate in_progress-to-open and ordinary unassignment requests remain separate transactions; open-and-assigned is valid if only the first succeeds.

## Expected tests or review evidence

- Matrix coverage for roles, requester/assignee scopes, valid/invalid sources and required eligibility.
- Ineligible, eligible and absent assignee reopening; rollback between status/assignment writes; denied customer resolved-to-resolved no-op.
- Terminal state, permitted closed-to-closed no-op, stale concurrent status changes and deactivation/reopening races per D04.
