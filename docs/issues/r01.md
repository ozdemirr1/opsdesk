# Publish the first OpsDesk backend preview

Local planning ID: R01. This is not a GitHub issue number.

Suggested priority: P1. Type: delivery.
Published issue: [#26](https://github.com/ozdemirr1/opsdesk/issues/26).

Snapshot of the initial published scope, 13 September 2026. Follow GitHub for
current status and scope discussion; this file is not a live progress tracker.
Status: awaiting user review; not implemented or published.

## Goal

Deliver the Month 03 backend preview with verifiable release evidence, carrying forward the missed Month 02 deployment outcome.

## Scope

- Select a bounded hosting/runtime and managed database approach compatible with the current non-Docker phase.
- Prepare environment configuration, release/migration procedure, public-preview boundaries, smoke checks and README deployment instructions.

## Out of scope

- Docker/Compose, frontend, AI, billing, production-scale operations.

## Acceptance criteria

- Resolve hosting, costs, secrets, access and preview-data policy before publication; do not select or purchase a service by implication.
- Deploy the reviewed feature scope only after its design dependencies and relevant CI checks are complete.
- Use separate deployment credentials and database; never point destructive tests at the preview database.
- Verify HTTPS, startup, safe errors/logs, registration/login and a tenant-scoped Ticket workflow with test accounts.
- Record actual release revision, verified URL, limitations, migration/rollback or recovery procedure; exclude secrets and personal test data.
- Review preview exposure controls before publication; unresolved security/release constraints block public release rather than being silently deferred.

## Expected tests or review evidence

- Local/CI release checks, controlled post-deploy smoke tests, isolation/unauthorized-access evidence and safe failure handling.
